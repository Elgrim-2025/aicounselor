# 학생 AI 상담 플랫폼 — Mock UI 구현 설계

## 배경
`Mock_UI_기획서_학생AI상담플랫폼_v2.html` (34개 화면 와이어프레임 + 주석)을 기반으로,
서버 없이 프론트엔드만으로 동작하는 "껍데기" 데모 페이지를 만든다. GitHub Pages에
정적 파일로 배포될 예정이다. 로그인 대신 "학생화면으로 접속 / 선생님화면으로 접속"
버튼으로 진입한다.

## 기술 스택
- 순수 HTML/CSS/JS, 빌드 도구 없음 (ES modules로 `<script type="module">` 사용)
- 해시 기반 라우터 (`location.hash`)
- 로컬 상태 저장은 `localStorage` (체크인, 채팅, PHQ-9 결과 등 사용자가 이번 세션에
  입력한 값만 유지; 새로고침해도 남도록)

## 파일 구조
```
index.html               진입점, 역할 선택 화면 포함
css/styles.css           디자인 시스템 (컬러/타이포/컴포넌트) — 실제 서비스 톤
js/data.js               목데이터 시드 + localStorage read/write 헬퍼
js/router.js             해시 라우터, 레이아웃 스위칭(학생 모바일 레이아웃 vs 상담사 데스크톱 레이아웃)
js/screens/student.js    학생 화면 렌더 함수 모음
js/screens/teacher.js    상담사·관리자 화면 렌더 함수 모음
js/components.js         공통 컴포넌트(뱃지, 모달/다이얼로그, 토스트 등)
```

## 진입 & 역할 전환
- `index.html` 최초 로드 시 역할 선택 화면(`#/select`): "학생화면으로 접속" /
  "선생님화면으로 접속" 두 버튼.
- 각 역할 레이아웃 상단(또는 사이드바 하단)에 "역할 전환" 버튼을 두어 `#/select`로
  언제든 돌아갈 수 있게 한다.
- 원본 로그인 화면(F-01)의 자격증명/동의 게이트 로직은 데모 목적상 생략한다(사용자
  명시적 요청). 단, 동의 철회 UI(F-33 설정 화면)는 학생 화면에 그대로 유지한다.

## 화면 범위와 우선순위 처리
전 34개 화면을 내비게이션에 노출한다.

**P0/P1 — 실제 인터랙션 동작**
- 학생: 채팅(F-02, 의도 분류 기반 고정 템플릿 응답), 기분 체크인(F-03), 자가진단
  목록(F-04/F-25), PHQ-9 응시(F-04, 9번 문항 오버라이드), PHQ-9 결과(F-04), 상담
  요청(F-09/10/34), 설정/동의철회(F-33)
- 상담사·관리자: 대시보드(F-12/28), 알림센터(F-13, 등급잠금해제 시 사유 입력 다이얼로그),
  학생상세(F-14), 학생관리(F-12), 상담세션+RAG추천(F-15/16/17), 학교폭력접수(F-18/19/20,
  48시간 카운트다운), 감사로그(F-11, 체인검증 버튼), 키워드사전관리(F-11), 임계치설정(F-07)

**P2 — "준비 중" 처리**
- 학생: 페르소나 설정(F-21), 감정일기(F-24), 검사결과 24종 통합 리포트(F-26), 마음편지함
  (F-23), 주간 리포트(F-27)
- 상담사·관리자: 그룹관리(F-29), 계정관리/대량생성(F-30~32)
- 네비게이션에는 노출하되 진입 시 잠금 아이콘 + "준비 중입니다" 안내만 표시.

## 레이아웃
- 학생: 모바일 폭(최대 ~430px) 중앙 정렬, 상단바 + 콘텐츠 + 하단 탭(채팅/감정일기/검사/리포트).
  기획서의 "폰 프레임" 장식은 제거하고 실제 반응형 모바일 웹앱처럼 전체 화면 사용.
- 상담사·관리자: 데스크톱 전체 폭, 좌측 사이드바 + 메인 콘텐츠. 사이드바 항목:
  대시보드 / 알림센터 / 학생관리 / 그룹관리(P2) / 계정관리(P2) / 감사로그 / 학교폭력접수 /
  키워드사전관리 / 임계치설정.

## 데이터 모델 (js/data.js)
- `students`: 가명 ID, 그룹, 등급(L1/L2/L3), 잠금여부, 최근 산출시각, 스파크라인 값,
  보정확률/CI (기획서 예시: STU-0231 L3 미해결 잠금, STU-0117 L2, STU-0198 L1 처리완료 이력)
- `alerts`: 알림 목록(등급, 산출방식 KEYWORD_OVERRIDE/MODEL/PHQ9_ITEM9_OVERRIDE, SHAP 근거,
  상태)
- `auditLog`: append-only 이벤트 목록(시각, 이벤트유형, 대상, 처리자, 해시)
- `keywords`: 마스킹된 키워드 목록 + 카테고리
- `thresholds`: `{t1: 0.35, t2: 0.65}`
- `chatIntents`: 의도별 고정 응답 템플릿 셋(자유 입력 텍스트를 받아 간단 키워드
  매칭으로 의도를 고르고 해당 템플릿 중 하나를 반환하는 목업 로직)
- 사용자 입력 반영: 체크인 저장, 채팅 발화, PHQ-9 응답은 `localStorage`에 append하고
  새로고침 후에도 유지되도록 한다.

## 핵심 인터랙션 목업 로직
- **채팅**: 자유 텍스트 입력 → 키워드 매칭으로 의도(고민/우울/친구문제/기타) 분류 →
  해당 카테고리 템플릿 중 하나를 봇 응답으로 표시. 위기 키워드(자해/자살 등 목업
  키워드 셋) 포함 시 별도 위기 안내 문구 + 상담사 알림 뱃지 노출.
- **PHQ-9**: 9문항 순차 진행, 각 0~3점. 9번 문항 1점 이상이면 총점과 무관하게
  결과 화면에 "상담사 확인 중" 배지 노출 + 알림센터 목데이터에 새 알림 추가(선택적
  연동, 데모 리셋 시 초기화).
- **알림센터 등급잠금해제**: 클릭 시 2차 확인 다이얼로그 + 사유 입력 필수, 입력 전
  확인 버튼 비활성.
- **감사로그 체인검증**: 버튼 클릭 시 "체인 무결성 검증 완료 — 불일치 없음" 토스트/메시지.
- **학교폭력접수 타이머**: 48시간 중 임의 남은 시간을 setInterval로 초 단위 카운트다운,
  24h/44h 경과 구간에서 경고색 전환.
- **임계치 설정**: 슬라이더(드래그 가능한 range input)로 T1/T2 조정, 저장 시 사유 입력
  다이얼로그.

## 디자인 시스템
- 컬러: 기획서의 accent(#3355ff), 등급색(L1 초록/L2 주황/L3 빨강)을 유지하되 실제
  서비스 톤으로 채도/명도 다듬기(카드, 그림자, radius 등 추가).
- 타이포: 시스템 폰트 스택(-apple-system, "Pretendard", "Apple SD Gothic Neo", sans-serif).
- 공통 컴포넌트: 카드, 뱃지(등급/상태), 모달(2차 확인용), 토스트, 바텀시트(모바일).

## 제외 범위
- 실제 인증/서버 연동, 실제 LLM 호출, 실제 알림(SSE) 없음 — 전부 목업.
- 만 14세 미만 법정대리인 동의 플로우 등 기획서에서도 "UI 범위 밖"으로 명시된 항목은
  구현하지 않는다.
